Intent Router

Tier 2 stops treating every capture as a task. It decides what kind of thing this is first, then only computes what that kind actually needs. All 5 open design gaps are resolved below. The two panels at the bottom are the actual working mockups, live and interactive in this same file — not screenshots.

Philosophy check (don't violate this while building):
  • Nothing here blocks capture. Tier 1's "insert first, classify after" safety net is unchanged.
  • Nothing here writes real data automatically. Every intent besides task ends in a tap-to-confirm, never an auto-write.
  • No new picker, no menu, no "which agent do you want" screen. Routing is invisible; the person never chooses a mode.
  • The assistant advises, it never decides. Nothing — including the consult conversation — is allowed to conclude, summarize, or file anything on the person's behalf.

2. Step 1 — two gates, with required evidence (Gap 1)

GATE 1 — Is this a plain task/capture, or does it need special intent handling?
  Requires a literal snippet from the text as proof before it can say "special"
  → no matching snippet found → capture_intent stays 'task', skip Gate 2
  → snippet found            → go to Gate 2

GATE 2 — (only runs if Gate 1 found evidence) Which kind of special intent?
  → person_note / outcome_report / consult / decision
Gap 1 — resolved: same pattern as the existing business_evidence guard. No evidence, no exception — falls through safely to task.

3. Data model

entries — new columns:
  capture_intent        text NOT NULL DEFAULT 'task'
  intent_status          text NULL  (processing | pending_confirm | confirmed | dismissed)
  intent_person_id       uuid NULL → people.id
  intent_delegation_id   uuid NULL → delegations.id
  intent_payload         text NULL
  intent_evidence        text NULL  (the literal snippet Gate 1 pointed to)

person_aliases — NEW table (Gap 2):
  id             uuid PK
  alias_text     text
  person_id      uuid → people.id
  confirmed_at   timestamptz
  -- only trusted if new capture's context still matches that person's history

4. Per-intent behavior, all gaps resolved

person_note — Gap 2

Ambiguous name match → ask, don't guess — confirm chip shows real candidates. Confirmed answers stored as aliases, but re-verified against that person's actual history every time, so a stored shortcut can't silently drift wrong later.

outcome_report

Same alias-aware person matching. 0 matches → falls back to task. 2+ matches → ask, don't guess, same as person_note. Exactly 1 → confirm chip opens the existing closeout prompt.

consult — Gap 5

  • Stays on Tier 2 (async). Auto-opens full-screen if still on Board when resolved; toast + waiting card otherwise.
  • Never concludes anything — no auto-summary, nothing written when it ends. Ends when the person stops replying.
  • Needs short-term multi-turn context only while actively open — not persisted afterward.
Gap 5 — resolved: the assistant advises, never decides. No closure-detection logic needed — the universal processing state already covers the whole time it's open.

decision

Tagged only. No destination built yet — do not build one until explicitly scoped.

5. Universal "processing" state — Gap 4

  • Applies to any row Tier 2 hasn't finished with — not just consult.
  • Grayed out, pulsing, visibly unresolved — never silently looks finished when it isn't.
  • Race condition rule, now universal: if the person acts on a row before Tier 2 finishes, their action always wins — Tier 2 flags quietly instead of overwriting.
  • Reference motion: the logo's dot lifts off, orbits the mark while processing, drops back into place when resolved — live demo below.

6. Confirm chip dismiss/timeout — Gap 3

Neither "No" nor a timeout resolves silently. One soft two-tap follow-up appears instead:
"Got it — keep this as a regular task, or clear it?" → [ Keep as task ] / [ Clear it ]
